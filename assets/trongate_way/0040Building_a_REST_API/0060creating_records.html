[meta-description]Build the POST /countries_api/create endpoint in Trongate v2: reading JSON input, validating fields, inserting records, and returning 201 responses.[/meta-description]

Creating Records

The create() endpoint accepts a JSON payload, validates it, inserts a new record, and returns a 201 Created response. This is the first time we need to read a JSON request body.

Reading JSON Input

HTML forms send data as application/x-www-form-urlencoded, which PHP reads via $_POST. API clients send application/json instead, which fills neither $_POST nor $_REQUEST. You could reach for php://input and json_decode() by hand, but Trongate's post() helper already does it: it reads whichever input the request carries - application/x-www-form-urlencoded, multipart/form-data or application/json - and hands it back as an associative array.

[code=php]$data = post(); // the whole payload $title = post('country_title'); // a single field[/code]

So there is no JSON parsing helper to write. The controller calls post() directly and handles the two ways a payload can be unusable: malformed JSON, which post() reports by throwing an exception, and an empty body, which comes back as an empty array.

post() also supports dot notation for nested keys - post('country.name') - trims and collapses whitespace with post(null, true), and can cast numeric strings with post(null, false, true). For this endpoint the plain form is enough.

Validation

The validation helper checks the required fields and returns an array of error messages:

[code=php]public function validate(array $data): array { block_url('countries_api/validate'); $errors = []; if (!isset($data['country_title']) || trim($data['country_title']) === '') { $errors['country_title'] = 'Country name is required.'; } elseif (strlen(trim($data['country_title'])) < 2) { $errors['country_title'] = 'Country name must be at least 2 characters.'; } elseif (strlen(trim($data['country_title'])) > 100) { $errors['country_title'] = 'Country name must not exceed 100 characters.'; } if (!isset($data['country_code']) || trim($data['country_code']) === '') { $errors['country_code'] = 'Country code is required.'; } elseif (strlen(trim($data['country_code'])) !== 2) { $errors['country_code'] = 'Country code must be exactly 2 characters.'; } return $errors; }[/code]

Each field error is keyed by the field name, making it easy for the client to display errors next to the correct input.

The Controller Method

[code=php]public function create(): void { $this->authenticate(); try { $data = post(); } catch (Exception $e) { http_response_code(400); echo json_encode([ 'error' => 'Invalid JSON payload.' ]); return; } if (!is_array($data) || empty($data)) { http_response_code(400); echo json_encode([ 'error' => 'Missing JSON payload.' ]); return; } $validation_errors = $this->validate($data); if (!empty($validation_errors)) { http_response_code(400); echo json_encode([ 'error' => 'Validation failed.', 'fields' => $validation_errors ]); return; } $new_id = $this->model->insert($data); http_response_code(201); echo json_encode([ 'message' => 'Country created successfully.', 'id' => $new_id, 'country' => $data ]); $this->log_request('create'); }[/code]

The 201 Created Status

Note the use of http_response_code(201). The 201 status code specifically means "Created" - it tells the client that a new resource was successfully created as a result of their request. This is more precise than 200 (OK) and is a REST best practice.

The Model Insert Method

[code=php]public function insert(array $data): int { $insert_data = [ 'country_title' => trim($data['country_title']), 'country_code' => strtoupper( trim($data['country_code']) ) ]; return $this->db->insert($insert_data, 'countries'); }[/code]

The model method cleans the data before inserting: it trims whitespace and uppercases the country code for consistent formatting. The $this->db->insert() method returns the ID of the newly inserted record.

Testing

[code=bash]# Successful creation curl -X POST \ -H "Trongatetoken: your-token" \ -H "Content-Type: application/json" \ -d '{"country_title":"New Country","country_code":"NC"}' \ http://localhost/countries_api/create # Missing required field curl -X POST \ -H "Trongatetoken: your-token" \ -H "Content-Type: application/json" \ -d '{"country_title":"Incomplete Country"}' \ http://localhost/countries_api/create # Invalid JSON curl -X POST \ -H "Trongatetoken: your-token" \ -H "Content-Type: application/json" \ -d 'not valid json' \ http://localhost/countries_api/create # Empty body curl -X POST \ -H "Trongatetoken: your-token" \ -H "Content-Type: application/json" \ http://localhost/countries_api/create[/code]

Each test case exercises a different response path: 201 for success, 400 with field errors for validation failure, 400 for malformed JSON, and 400 for an empty body. The last two are worth testing deliberately - they are the paths where a clumsy implementation returns a 200 with a PHP warning inside the JSON instead of a clean error.
