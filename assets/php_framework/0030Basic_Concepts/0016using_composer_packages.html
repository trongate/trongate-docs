[meta-description]Trongate never needs Composer - but it won't stand in your way. Install a package, load one line in public/index.php, then reach for it with a use statement. Here's the whole contract for using Composer packages in Trongate v2.[/meta-description]

Using Composer Packages

Trongate works perfectly without Composer. It also works perfectly with it. The previous page covers why and when - this one covers how, and the how is short enough to learn in one sitting.

Composer Is Optional

Nothing in Trongate requires Composer. The framework ships with no dependencies and no vendor/ folder, and it won't complain if you add one.

So reach for Composer only when it earns its place - a payment SDK, a PDF library, a mature date library. Otherwise write it yourself. That's the Native PHP way!

Install and Load a Package

Install whatever you want from the root of your application, then hand Composer's autoloader to Trongate. That's one command and one line:

[code] # from your application root composer require dompdf/dompdf # public/index.php require_once '../engine/ignition.php'; require_once APPPATH . 'vendor/autoload.php'; // <- the only addition $init = new Core; [/code]

Those three lines around the new one are the stock contents of public/index.php. Trongate does not load Composer's autoloader for you, so this line is what wakes it up - for every module, on every request.

The two autoloaders keep out of each other's way. Trongate's own loader only ever looks inside engine/ and modules/. Composer's loader only ever looks inside vendor/. Composer registers itself first, so anything it can resolve wins - which is exactly what you want.

Use It In Your Module

Add a use statement at the top of your module and get on with it. This works in controllers, models and views alike:

[code=php] <?php use Dompdf\Dompdf; class Invoices extends Trongate { public function test(): void { $dompdf = new Dompdf(); $dompdf->loadHtml('<h1>Hello from Trongate v2</h1>'); $dompdf->render(); header('Content-Type: application/pdf'); echo $dompdf->output(); } } [/code]

Visit /invoices/test and you get a real PDF, produced by a Composer-installed package. That is the entire recipe - everything else is whatever the package's own documentation tells you to do.

One rule remains: the class declared in a Trongate module file must stay global (class Invoices extends Trongate). Trongate resolves it by file name, so it can't live inside a namespace. Imported classes can.

If a package ships CSS or JS rather than PHP, reference it straight from /vendor/ in your views - Trongate serves those files for you, so nothing needs copying around.

Two Other Places That Line Goes

At the top of a module file

If you're giving a module to somebody else, put the autoloader line at the very top of the module's controller file, immediately after <?php and before your use statements:

require_once APPPATH . 'vendor/autoload.php';

The module then works on a pristine copy of Trongate, and a fresh public/index.php never breaks it. That's the polite way to publish a module.

In a CLI or cron script

Scripts never touch public/index.php, so they have to bootstrap themselves. Trongate's own requires are path-relative, so chdir() into public/ first - skip that and you'll meet Failed opening required '../config/config.php':

[code=php] <?php chdir(__DIR__ . '/../public'); require_once '../engine/ignition.php'; require_once APPPATH . 'vendor/autoload.php'; Modules::run('invoices/test'); [/code]

If your script complains about $_SERVER keys, give it the basics (REQUEST_METHOD, HTTP_HOST, REQUEST_URI). Trongate likes to know what kind of request it's serving.

Housekeeping

Add /vendor/ to your .gitignore, but commit composer.json and composer.lock. Get comfortable with composer audit - it's now part of your maintenance routine, and that's the honest price of inviting in third-party code.

When Things Go Wrong

Two failures account for almost every confused afternoon:

  • A 500 with an empty response body means Composer's autoloader was never loaded. Trongate renders nothing because the failure happens before it gets a chance. Check that line in public/index.php first.
  • Access denied: assets must be in subdirectories means your module folder name contains _module. That string is reserved by the framework - Invoice_module won't work. Call it Invoices instead.

Advanced: you can also ship an entire module as a Composer package, so that composer require drops it straight into modules/. It works, but it needs a small installer plugin and it's strictly optional. The simple way to share a Trongate module is still to copy the folder.
