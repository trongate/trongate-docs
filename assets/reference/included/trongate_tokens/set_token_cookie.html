set_token_cookie()

public function set_token_cookie(string $value, int $expires): void

Description

Writes (or clears) the trongatetoken cookie, applying the framework's cookie flags.

This is the only place in the framework where the login cookie is written. Setting and clearing a cookie must use the same attributes, so both go through this method.

Parameters

Parameter Type Description Default Required
$value string The token to store. Pass 'x' when clearing the cookie. N/A Yes
$expires int Unix timestamp for expiry. Pass a time in the past to clear the cookie. N/A Yes

Return Value

Type Description
void This method does not return a value.

Example Usage

[code=php] // Remember-me login: generate the token, then store it as a cookie $expiry_date = time() + (86400 * 30); $token = $this->trongate_tokens->generate_token([ 'user_id' => $trongate_user_id, 'expiry_date' => $expiry_date ]); $this->trongate_tokens->set_token_cookie($token, $expiry_date); // Clear the cookie $this->trongate_tokens->set_token_cookie('x', time() - 86400); [/code]

Notes

  • Sets HttpOnly, so the cookie cannot be read by JavaScript.
  • Sets SameSite=Lax, so the cookie is sent on same-site requests and on top-level navigation to the site, but not on cross-site POST requests or cross-site subresource loads.
  • Sets path=/, so the cookie is available across the whole application.
  • Sets Secure when BASE_URL begins with https://. A site running on plain HTTP receives the cookie without the flag, exactly as it did before the flags were added.
  • These attributes are not configurable.
  • Normally there is no need to call this method: generate_token() writes the cookie when set_cookie is true, and destroy() clears it. Call it directly only from a module that has to emit the cookie itself.
